# 全身の遠隔操作の学習データ（`wholebody_make_data.py`）

人の動き（LAFAN1、CMU の BVH）を Microban に写し、学習タスク `Mjlab-Wholebody-Microban` の学習用・評価用の
HDF5 を作る。PICO の公開録画からは評価用のデータだけを作る。すべて CPU で動き、GPU は使わない。

```text
取得（fetch）→ 写し（retarget）→ 腕の反転を切る（finalize）→ 除外の規則と HDF5（build）→ 混ぜる（mix）
```

## 作り直しのコマンド

学習リポジトリのチェックアウトで次の 1 つを実行する。

```bash
uv run --locked python src/mjlab_microban/scripts/wholebody_make_data.py all --workers 12
```

- LAFAN1、CMU、G1 のモデル（PICO の録画を読むため）を、決まった版で `data/wholebody/raw/` に落とす。
  すでにあれば落とさない。LAFAN1 の zip は SHA-256 で、CMU は git のコミットで版を確かめる。
- 写し → 腕の反転の切り → 学習側の除外の規則と HDF5 → `mix` のリンク、の順に進む。
- `data/wholebody/raw/pico/` があれば PICO の評価用（`pico_eval`）も、
  `data/wholebody/raw/amass/smplx_g/` があれば AMASS（`docs/wholebody_amass_smplx.md`）も作る。
- かかる時間（このマシン、12 並列の実測）：取得 3.5 分（CMU 4.2 GB、LAFAN1 0.5 GB）、写し 約 8 分（LAFAN1 と CMU の 2625 本）、
  除外と HDF5 約 2 分。
- `--support` を付けると、Microban の ZMP が支えの範囲に入るように決まった順で目標を変えて写し、床に着いた足を止める（下の「ZMP を支えに寄せる」）。

段ごとにも回せる（`--sets` で対象を選ぶ。既定は lafan1 と cmu、元のファイルがあれば amass と pico_eval）。

```bash
S=src/mjlab_microban/scripts/wholebody_make_data.py
uv run --locked python $S fetch
uv run --locked python $S retarget --sets cmu [--only names.txt]   # names.txt: 写し直すクリップの名前
uv run --locked python $S finalize --sets lafan1 cmu pico_eval
uv run --locked python $S build --sets lafan1 cmu pico_eval
uv run --locked python $S mix --sets lafan1 cmu
```

1 本だけ写して見るとき、写しの品質の数字を並べるとき：

```bash
uv run --locked python $S file data/wholebody/raw/cmu/data/007/07_01.bvh --format bvh_cmu --out-dir /tmp/check
uv run --locked python $S render /tmp/check/07_01.npz        # 07_01.mp4、_sheet.png、_joints.png（CPU で描く）
uv run --locked python $S quality data/wholebody/gmr/cmu data/wholebody/cmu/quality.json
```

## 置き場所

すべて `data/wholebody/` の下で、git の対象外（`.gitignore`）。LAFAN1 は CC BY-NC-ND 4.0 なので、
写したもの（pkl、npz、HDF5）を含めて配らない。

| 場所 | 中身 |
|---|---|
| `raw/lafan1/` | LAFAN1 の BVH 77 本、`lafan1.zip`、`LICENSE_lafan1.txt`、`README_lafan1.md` |
| `raw/cmu/` | cmu-mocap の写し（`data/<被験者>/<被験者>_<番号>.bvh` 2548 本と索引 `cmu-mocap-index-text.txt`） |
| `raw/g1/` | G1 のモデル `g1_mocap_29dof.xml` と `LICENSE`（PICO の録画の順運動学だけに使う。メッシュは読まない） |
| `raw/pico/` | PICO の録画（手で置く。下記） |
| `gmr/<set>/` | 写しの出力（クリップごとの `.pkl`、`.npz`、`_report.json`、`_ik.json`）と `manifest.json`（胴の寄せの設定と、クリップごとの名前、元のファイル、説明）、`errors.json` |
| `<set>/retarget/` | 腕の反転を切った pkl。切った量は `<set>/finalize.json` |
| `<set>/{train,eval}/motion.h5`、`<set>/report.json` | 学習側の HDF5 と、種類ごとの量・外した割合 |
| `pico_eval/eval/motion.h5` | PICO の評価用（学習用はない） |
| `mix/{train,eval}/<set>.h5` | 学習用のセットの HDF5 へのリンク。学習も評価もこのフォルダを読む |

学習と評価：

```bash
# 学習
--env.commands.motion.motion-file data/wholebody/mix/train
# 評価（学習の種類がすべて評価にあることを求める）
uv run --locked python src/mjlab_microban/scripts/wholebody_benchmark.py --checkpoint <model.pt> \
    --motion-file data/wholebody/mix/eval --train-motion-file data/wholebody/mix/train
# PICO の評価用だけで評価する（評価用の種類だけを、同じ線で判定する）
uv run --locked python src/mjlab_microban/scripts/wholebody_benchmark.py --checkpoint <model.pt> \
    --motion-file data/wholebody/pico_eval/eval --eval-only-set --output-root artifacts/wholebody_pico
```

進み具合の線（胴の進んだ量を参照の進んだ量に射影した比が 0.5 以上）は、種類の名前によらず、参照の胴が片の判定する歩
（片の始めから 1 秒たったあと、下記）の間に 0.12 m 以上進む片を持つ種類すべてに掛かる。0.12 m は、片の終わりに胴の位置の
報酬の std（0.06 m）以内にいれば 0.5 に届き、立ち止まれば届かない長さ（0.06 / (1 - 0.5)）。PICO の歩き（`picoteleopit`、`picotwist`）や CMU の歩き（`cmuwalk`）にも掛かる。

### 評価の始め方と、暴れと倒れの線

評価（`src/mjlab_microban/wholebody/benchmark.py`）は、遠隔操作の始まりと同じ条件で、片ごとに回す。
遠隔操作では、ロボットは止まった HOME から、操縦者は立った状態から始め、ロボットが見る参照はそこから途切れずに続く。
参照が HOME から動きの途中の姿勢へ一瞬で跳ぶことはない。

- **片の始め**：参照で操縦者が静かに立っているフレーム（立ちのフレーム）。両足の足裏の最も低い角が床から 10 mm 以内、
  胴の傾きが鉛直から 30° 以内（倒れの線で参照が立っているとみなす角度。HOME は 10°）、胴の速さが 0.05 m/s 以下（歩きの胴の速さの
  中央値 0.12〜0.16 m/s の 3 分の 1）。10 mm は、PICO の評価用データでゆっくりで直立のフレームの高いほうの足裏が、75% で 7 mm、
  90% で 13 mm 以内（追跡の揺れ）であることから決めた。
- **置き方と最初の 1 秒**：関節は HOME で速さ 0、胴は HOME の高さと傾きで、参照の胴の水平の位置に置き、向き（yaw）を参照に合わせる。
  最初の 1 秒は、参照を片の最初のフレームに止めておき（操縦者が立って待つ間に、ロボットが HOME からその姿勢に入る）、判定しない
  （終わりの判定で失敗にせず、誤差も取らない）。そのあと参照をそのフレームから途切れずに流し、すべての歩を判定する。
- **片の切り方**：区間（評価用データの窓 1 つ）の最初の立ちのフレームから 1 つ目の片を始め、前の片の始めから 10 秒
  （`--clip-seconds`）以上たち、区間の終わりまで 10 秒以上残る最初の立ちのフレームで次の片を始める。片は次の片の始め（なければ
  区間の終わり）まで続く。寝て起きる、戦う、走るなど、立ちに戻らない動きは、長くても 1 つの片に丸ごと入る
  （PICO の評価用データの片は 1.1〜203 秒、平均 11.6 秒。学習の評価用データは 1.0〜36 秒）。
- **評価に入らないもの**：区間の最初の立ちのフレームより前と、立ちのフレームのない区間。HOME から参照を跳ばさずには入れないため。
  CMU の評価用の区間は各録画の最後の 20%、LAFAN1 の区間はデータが外すフレームで切れているので、動きの途中から始まるものが多い。
- **評価に入る秒数**（判定する秒数）：PICO の評価用データで 3543 秒のうち 2877 秒（picoany 537、picoteleopit 1448、picotwist 892）、
  学習の評価用データで 8604 秒のうち 4895 秒。どの種類も残る（最も少ないのは cmurun の 6 秒）。前の始め方（区間の始めから 10 秒ごとの片を、
  どのフレームからでも始め、参照を最初の歩から流す）は 3030 秒と 5807 秒を判定したが、参照が HOME から動きの途中の姿勢へ跳ぶため、
  最初の歩で片の 49〜59% が終わりの判定（胴・足・手の高さが参照から 5 cm）に掛かっていた。

成功、誤差、進み具合の線は、判定する歩（最初の 1 秒のあと）で取る。これに 2 つの線を足した。

- **暴れの線**（種類ごと、`leg_action_rate`）：脚 12 関節の、1 歩ごとのサーボの目標の変化の二乗和
  （報酬の `action_rate_l2` と同じ形、rad²）の、歩の平均が 3.36 以下。
  - 根拠：実機で暴れないと分かっている PICO の方策
    （`mjlab_microban_teleop_v12` の `2026-10-11_23-19-20_home_481503d292_pico_v13_v13g2`、`model_14999`）が、
    歩き（8 つの歩きの指令：前後 2 つの速さずつ、左右、その場の左右回り。腕は HOME、10 秒を 128 回）で 3.355。
    止まれ（16 回）は除いた。止まれは 0.0003 で、含めた 144 回では 2.98 になる。
  - 測る歩も同じにする：片の始めから 1 秒たったあと、倒れるまで。失敗した片も含める。
- **倒れの線**（PICO の評価用データ全体、`falls_per_minute`）：立っていた 1 分あたりの倒れの回数が 0.425 以下。
  - 倒れの定義：胴の傾き（鉛直から）が 45° を超え、そのとき参照の胴の傾きが 30° 未満（参照が寝ているときは倒れにしない）。
    HOME の胴は鉛直から 10° 前に傾いているので、45° は HOME からさらに 35° 傾いたところ。PICO の方策の押しの判定も同じ数え方。
    片の始めから終わりまで見る。終わりの判定のあとも片の終わりまで回し続けて見る。
  - 時間あたりで数える理由：片の長さはばらばら（PICO の評価用データで 1.1〜203 秒、平均 11.6 秒）で、根拠の押しの判定は 1 回 6 秒。
    片の数で割ると、割合が片の長さで変わる。そこで、倒れの数を、片が倒れるまでに回った時間（倒れなければ片の長さ）の和で割る。
  - 根拠：上の PICO の方策の押しの判定（止まれと 8 方向の歩き、毎秒 0.4 m/s で押す、1 回 6 秒を 144 回）で、
    同じ傾きの決まりで 6 回倒れた（144 回のうち 6 回）。立っていた時間の和は 846.58 秒なので、1 分あたり 0.425 回。
    実機で動かしている方策と同じ頻度までを認める。
  - 線は評価だけのデータ（`--eval-only-set`、操作者の動きである PICO の録画）にだけ掛ける。
    学習の評価用データの倒れの頻度は報告するが、線にしない。操作では使わない動き（全力の走り、跳び、倒れ込み）を含み、
    終わりの判定は成功率の線ですでに見ているため。

報告の表（`<model>-kinds.csv`）には、種類ごとに `judged_seconds`（判定した秒数）、`falls_per_minute`（立っていた 1 分あたりの倒れ）、
`leg_action_rate`（暴れの線の数字）を足した。判定（`verdicts.final`）には `kinds_above_action_rate_line`、`falls_per_minute`、
`fall_ok` が入る。

書き出し（`src/mjlab_microban/scripts/wholebody_export.py`）は、同じチェックポイントの報告を 2 つ求める。
学習の評価用データの報告（`--benchmark-report`）と、評価だけのデータの報告（`--eval-only-report`、倒れの線が掛かるもの）で、
どちらも、立ちのフレームから HOME で始める評価（報告の `metadata.start` が `standing`）で合格していること。2 つの報告の SHA-256 は ONNX のメタデータに入る。

GPU の物理の計算は回ごとに和の順が変わり、ビット単位では再現しない（torch の決定的な設定でも変わらない。64 片を 2 回回すと 63 片の数字が違った）。
同じチェックポイントと seed でも、片ごとの結果は回ごとに少し違う。本番の学習の model_10000 を PICO の評価用データで 2 回回すと、
489 片のうち 5 片で成功が入れ替わり、picotwist の成功率は 91% と 88%、倒れは 1 分あたり 1.32 回と 1.34 回だった。
線から数点以内の値は、回によって線の上にも下にもなりうる。

| 場所 | 出どころ | 中身 |

| `raw/pico/any4hdmi/manifest.json`、`*.npz` | EGalahad/sim2real の real_pico の録画。配布元の場所は未確認 | 13 本、30 fps |

基準の立ち姿は、録画の元ごとに静かに立つフレームから作る。

## 写し方（`src/mjlab_microban/wholebody/retarget/`）

- GMR の IK（`gmr/`、Teleopit 経由の写し。GMR は MIT、Teleopit は Apache-2.0。ライセンスは `gmr/LICENSE`、変更点は `gmr/motion_retarget.py` の冒頭）で解く。
- BVH の読み込みは自前（`skeleton.py`）。GMR 同梱の BVH 読み込み（`lafan_vendor`、CC BY-NC-ND 4.0）は入れていない。
- 人の基準の立ち姿（骨格から作る。LAFAN1 は被験者ごとの静かに立つフレームから）を、HOME（`config/home_pose.yaml`）に重ねる。基準の立ち姿を写すと HOME に一致する。
- 胴の傾きは骨盤から首の付け根への向き、向き（yaw）は左右の肩の線から取る。手足は胴の座標でねじれのない回転で回すので、体の向きによらない。
- 床は、学習側の衝突形状の最も低い点を、人の体の浮き（足、または床に着きうる部位）× 縮尺の高さに置く。
- 首は写さない（HMD から別に動かす）。
- 詳しい決め方は `core.py` の冒頭にある。IK のロボットのモデルは `robot.xml` に関節の中心の site を足したもので、実行時に作る（`model.py`）。

確かめ（`tests/test_wholebody_retarget.py`、合成の骨格）：基準の立ち姿が HOME に写る、人の左腕と左足を上げるとロボットの左手と左足首が上がる
（右は動かない）、左右に映した動きが左右に映したロボットになる（2 mm 以内）、動きを回して動かしても関節角が変わらない（1e-6 rad 以内）、
SMPL-X の読み込みが体のモデルの式と一致する、寄せると片足立ちの ZMP が支える足の支えの範囲に入り（寄せる前は中央値 37 mm 外、寄せたあと
外への距離 p95 が 1 mm 未満、最大 2 mm 未満で、9 割のフレームが 1〜4 のどれかの段で入る。当てはめが片側からになる最後の 4 フレームを除く。
横のずらしは上限 40 mm に届き、残りを傾きと足の置き場所が入れる）、その足は足の置き場所の変更の分を除いて動かず（3 mm 以内）、
床にあり続けて滑らず（床に着いた点の速さ p90 が 1 mm/s 未満）、胴から見た手の位置は変わらない（3 mm 以内）。
`tests/test_wholebody_support.py`：止まった姿勢の ZMP は重心の真下、体ごと 2 m/s² で加速すると重心の高さ × 2 / g だけ後ろ（寄せない
写しからの変えた分として与えても同じ）、足の裏の凸包を 10 mm と 5 mm 縮めた大きさ、余裕の 2 倍より細い接地面は中央の線になる、
余裕と各上限は 0 以上の有限の値に限る、床に着いた足は床に着いた点の中心が動かず（滑りが 0）、平らな間はその場で人の足と同じだけ
向きを変え、かかとが上がると爪先の縁で転がり、離れたあとは跳ばずに止めをやめる、フレームが入った段は最後まで入ったままの最初の段。
`tests/test_wholebody_make_data.py`：一部のクリップを、そのセットと違う寄せの設定で写し直すことは断る。

作り直しの再現性：

- リポジトリの環境（`uv.lock`：mujoco 3.13.0、numpy 2.3.5、scipy 1.18.1、mink 1.3.0）では、同じ元からは同じ写しになる
  （並列の数 1 と 4 で同じ）。
- いまの学習データ（作業場所で作り、小さな学習に使ったもの）は、版の違う環境（mujoco 3.15.0、numpy 2.2.6、scipy 1.15.3）で作った。
  このコマンドで写し直すと、ほとんどのクリップは一致する（CMU は 1e-9° 以内、PICO は 103 本中 101 本が 0.0011° 以内）が、
  IK の解の分かれ目にあるクリップは変わる。LAFAN1 push1_subject2 は最大 0.11°、PICO picotwist_0807_yanjie_walk_037 は最大 2.1°、
  picotwist_0807_yanjie_walk_044_p0 は腕の解が入れ替わり、412 フレーム中約 280 フレームで最大 190° 違う
  （腕の反転のフレームも 168 → 170 になり、`finalize` で切ったあとの区間の長さが変わる）。
- そのため、作業場所で作ったデータは、このコマンドでは完全には再現できない。このコマンドで作り直したデータで学習し直せば、
  そのあとは同じ環境で再現できる。

## ZMP を支えに寄せる（`--support`、既定は寄せない）

Microban は体に比べて両足の間隔が広い（HOME の足の裏の中心の間隔 93 mm、脚の長さの 0.75。人は 0.2〜0.25）。また体が小さいので
倒れ込みが速い（重心の高さで sqrt(h / g) = 0.11 秒。人は 0.3 秒）。人の動きを人の速さのまま縮めて写すだけでは、片足のときに
Microban の ZMP が支える足の外に出る（全データの片足のフレームのうち、ZMP が支えの範囲にあるのは 1%）。`--support` を付けると、
写した参照の Microban の ZMP が支えの範囲 S に入るように、決まった順で、必要な分だけ目標を変えて写し、床に着いている足をその場に
止める（`src/mjlab_microban/wholebody/retarget/support.py`）。

```bash
uv run --locked python $S all --support --workers 6                                # 既定の余裕と上限（1 並列あたり約 2.2 GB）
uv run --locked python $S retarget --sets cmu --support --support-margin-mm 15      # 余裕を変える
uv run --locked python $S retarget --sets cmu --support --support-max-tilt-deg 0    # 胴の傾きを使わない
```

変える順。前の段で ZMP が S に入らないフレームの近く（0.2 秒以内）だけ、次の段を許す。1〜4 でも入らないフレームはそのまま残す。

1. 胴の水平のずらし（前後と左右。腕は胴に対する姿勢を保って一緒に動く。床に着いていない足も胴と一緒に動き、着く前の 0.2 秒で
   着く位置へなめらかに戻る）。上限は左右 `--support-max-lateral-mm`（既定 40）、前後 `--support-max-forward-mm`（既定 30）。
2. 胴の傾き（左右の roll と前後の pitch。両股の中点のまわり。腕も一緒）。上限 `--support-max-tilt-deg`（既定 10、それぞれ）。
3. 足首の左右の傾き（足の裏を足の前後の軸のまわりに回す）。上限 `--support-max-ankle-roll-deg`（既定 5）。
4. 足の置き場所（床に着いている区間ごとに 1 つの水平のずれ。着いている間は一定、離れている間に前後の区間の値へつなぐ）。
   上限 `--support-max-foot-mm`（既定 20）。

- 上限と余裕は 0 以上の有限の値で、`--support` と一緒にだけ使える。0 にした手段は使わない。使った設定はクリップごとの
  `_report.json` の `support_shift` と `gmr/<set>/manifest.json` の `support_shift` に残る（寄せないときは null）。
  `retarget --only` で一部だけ写し直すとき、manifest と違う設定は断る。寄せを入れる前の manifest（クリップの一覧だけ）は寄せなしとして読む。
- 数字は `_report.json` の `zmp_in_support`（寄せる前 `before`、段ごと `stages`、寄せたあと `after` の、片足・両足・足以外も着く・
  部位が離れる瞬間それぞれの S の中の割合と外への距離、どの段で入ったか `stage_reached`）、`support_changes`（各手段の大きさと
  使ったフレームの割合）、`standing_foot_speed_mm_s_p50_p90_max`（立ち足の滑り）にある。フレームごとの値は `.npz` の
  `zmp`、`zmp_outside`、`contact`（寄せたあと）、`zmp_before`、`zmp_outside_before`、`contact_before`（寄せる前）、
  `zmp_stage`（入った段：0 寄せる前から、1〜4、5 入らない、-1 判定しない）、`support_shift`（世界の座標、m）、`support_tilt`
  （roll と pitch、rad）、`support_ankle_roll`（左右、rad）、`support_foot`（左右の足の置き場所のずれ、世界の座標、m）。

決まり：

- 支えの範囲 S(t)：床に着いているすべての部位の接地面の凸包を、縁から余裕（既定 10 mm）だけ内側へ縮めた範囲。縮めると何も
  残らないほど狭いときは、凸包の最も内側の点の集まり（中央の線か点）。接地面は、その部位の学習の衝突形状のうち、最も低い点から
  10 mm 以内の部分を上から見たもの。
- 部位が床にあるか：人のその部位が床の高さにあり（足は基準の立ち姿の高さ、ほかは寝たときの高さ）、床に沿う速さが脚の長さの
  0.8 倍毎秒未満で、Microban のその部位が床から 25 mm 以内（学習側が支えとみなす高さ）のとき。または、Microban のその部位が
  床から 5 mm 以内にあり、0.1 m/s より遅いとき。2 フレーム以下の途切れは埋め、1 フレームだけの接地は除く。寄せた写しの部位は、
  寄せたあとの姿勢から同じ決まりで判定し直す。数字はすべてこの判定で数える。クリップの最初と最後の窓の半分（4 フレーム）は、
  当てはめが片側からになるので判定しない（寄せる前も後も）。
- 寄せない区間：何も床に着いていないフレーム（跳ぶ、走る、寝る・這う：胴が 45° を超えて倒れ、足以外が床にある姿勢は床に
  何も着いていないとみなす）と、足以外の部位が床にあるフレーム（膝、手、胴）。変更は 0 にし、前後 0.2 秒で 0 へつなぐ。
- 部位が離れる前：接地の変わらない区間の最後の 0.3 秒で、ZMP を残る支えの中へ移す（残る支えからの距離の上限を、床にある最後の
  フレームで 0 になるよう線形に縮める）。そのフレームと離れた最初のフレームの重みはほかの 10 倍。

ZMP の求め方：

- Microban の全身の動力学（`robot.xml`、学習で使う質量と慣性）で求める。写した qpos の時系列を `mj_inverse`（接触なし）に通し、
  浮いた根に要る力とモーメント（床が与えるべきもの）の水平のモーメントが 0 になる床の点。腕や胴の角運動量の変化も入る。
- 速度と加速度：人の動き（寄せない写し）の分は 0.3 秒の 3 次の当てはめ（取り込みの細かい揺れを除くため）、変えた分（寄せない写し
  からの差）は 5 フレーム（0.17 秒）の当てはめで取る。0.3 秒の当てはめは 2 Hz の加速度を 0.78 倍、3 Hz を 0.56 倍に見るので、
  それに対して解くと、当てはめに見えない速い動きに頼った変更になる。5 フレームは 2 Hz を 0.94 倍、3 Hz を 0.86 倍に見て、
  IK の解のフレームごとのばらつき（胴の高さ 0.7 mm、関節で最大 20 mrad）を中央差分の 0.22 倍に抑える（中央差分では、そのばらつきで
  ZMP が中央値 4 mm 動いた）。

解き方：

- 変更（ずらし、傾き、足首の傾き）は、節が 0.1 秒おきの 3 次の B スプライン（0.2 秒おきでは、上限や股の制限をすべて外しても、
  LAFAN1 walk3 の片足のフレームの半分が外に残った。倒れ込みが 0.11 秒と速いため）。足の置き場所は着く区間ごとに 1 つ。
- 1 回目はクリップ全体を 1 のずらしだけで解く。そのあと段ごとに（1 をもう一度、2、3、4 の順に）、その時点で ZMP が S の外にある
  フレームの近くだけを、その段までの手段で解き直す（前の段の手段もその近くでは解き直す）。新しい手段はそのフレームから 0.2 秒
  以内だけで使え、その外では 0。
- 最小二乗の項：ZMP の許す範囲の外への距離（S の 2 mm 内側を狙う。30 mm までは 2 乗、その先は 1 次：跳ぶ前の踏み切りのように、
  どう変えても入らない ZMP に引かれないため）の重みを、どの手段を上限まで使うより 1 mm の外れのほうが重くなるようにする。
  各手段の大きさ（ZMP を 1 mm 動かすあたりで、ずらし ＜ 傾き ＜ 足首 ＜ 足の置き場所。同じ段の中でも前の手段から使う）、加速度、
  前後のずらしの速さ（胴の進み方を保つ）。ほぼ守らせる制限：立ち足が伸び切っても足首に届かなくなる変更（胴を最大 20 mm 下げる
  分を入れて決める）、立ち足の股の roll が範囲の端から 1° 以内に入る変更、上限を超える変更。すでに越えているものは悪化だけ止める。
- 変更に対する ZMP と股の roll の応答は数値で取る。変更を少し（10 mm か 0.03 rad、0 に近づく向き）動かして姿勢を作り直し
  （下の「写し方」の動かし方）、各フレームの ZMP を求め直す。応答はその段の始めに、その時点の解のまわりで取り直す。求めた
  変更で姿勢を作り直し、実際の ZMP からもう一度解く（1 回目 2 回、段ごと 1 回）。ZMP の外れが最も小さいものを残す。足の置き場所の ZMP への応答は、
  動く脚の質量の割合（膝から下と腿の半分、全体の 12%）で近似し、支えの範囲そのものは足と一緒に動かす。
- 最初と最後の窓の半分（4 フレーム）は ZMP を制限せず、変更もそこでは動かさない。

足を止める（床に着いた足を滑らせない。ZMP を求める前に行い、寄せの間も守る）：

- 床に着いている足：接地の決まりで床にある足（S と学習側が数えるもの）。寄せたあとのロボットの姿勢で判定する。
- 床に着いている点：足の裏のうち、その足の一番低い点から 1 mm 以内の点。
- 決まり（止め方と滑りの測りで同じ。`support.hold_feet`、`support.slide_speed`）：前後のフレームの両方で床に着いている点の
  中心は、水平に動かない。足はその中心のまわりに、人の足と同じだけ向きを変えてよい（足の裏で回る）。爪先（かかと）の縁だけが
  着いていれば、その縁のまわりに転がる。着いた最初のフレームは人の目標のまま（それまで浮いていた点は数えない）。足が離れた
  あと、止めるための補正は 0.2 秒でなめらかに消す。
- 止めた足の目標は、着いている区間の頭から 1 フレームずつ順に作る（人の目標を、床に着いている点の中心が動かないように動かす。
  高さは床の上を転がる高さと人の足首の高さの高い方）。
- IK は人の目標に一番近い姿勢を選ぶ（重みは GMR のまま）。そのあと、床に着いている足の脚の 6 関節だけを解き直して、足を止めた
  目標に合わせる。脚が届かないときは、胴を最大 20 mm 下げ、それでも届かない後ろ足（蹴り出す直前）は届く高さまで持ち上げる
  （床から離れるので滑りではない。Microban の脚は歩幅に対して人より短い）。脚だけでは足を目標の 2 mm 以内に持ってこられない
  とき（股の pitch や roll が範囲の端にある）と、脚だけで合わせると部位どうしが学習側の衝突の形で 3 mm より深く重なるとき
  （深くしゃがんだときの腿と胴、狭く立ったときの足首と脛。学習側は 5 mm で切る）は、IK の脚のままにする（そこでは足が滑る。
  滑りとして数える。下の「滑りが残るところ」）。
- 床に着く前の 0.2 秒と離れたあとの 0.2 秒は、脚を目標に合わせる分を 0 と 1 の間でなめらかに（smoothstep）入れ、抜く。一度に
  切り替えると、伸びた膝の近くでは足の数 mm が膝の数十度になり、学習側が関節の跳びとして切る。
- 判定と止め方を合わせる：止めると足の姿勢が変わり、床に着いているかの判定も変わる。判定し直して違うフレームを解き直すのを、
  一致するまで（最大 3 回）繰り返す。寄せる前の写しで行ってから ZMP を求め、寄せたあとにも行う（変わったフレームの ZMP は
  判定し直す）。
- 足の置き場所（4）は、着く区間ごとの目標を動かしたうえで、その位置で止める。
- 滑り：前後のフレームの両方で床に着いている点の中心の水平の速さ。5 mm/s（30 fps で 1 フレーム 0.17 mm）を超えると滑りとする
  （`support.SLIDE_MM_S`）。
- 足の向きは人と同じだけ回す（床に着いた点の中心のまわり）。人の回りの一部だけを足で回し、残りを脚のねじりで受ける形（足で
  回す割合を、人の足の回る速さと接地の広がりの線形の式にする）も試したが、見本 6 本で、寄せない写しからのずれ（IK の重みで
  足した値）は割合 1 で 0.27、0.5 で 0.41、0 で 0.74 と、回る速さ（0〜30、30〜90、90〜180、180°/s 以上）と接地の広がり
  （20 mm 未満と以上）のどの区分でも 1 が一番小さく、滑るフレームも減らなかった（57.5、58.0、58.1%）。

写し方（寄せるときだけ）：

- 寄せない写しは GMR の IK で解き、各フレームを最初の解から収束するまで（誤差の減りが 1e-5 未満、最大 50 回）解き直す（磨く）。
  最初の解は前のフレームから順に解いて GMR の打ち切り（0.001）で止まっていて、解き直すと関節が最大 70 mrad 動き、そのばらつきが
  変えた分の加速度に入る。
- 寄せの変更をしたフレームは、IK で解き直さず、磨いた解を動かして作る：胴と腕は変更どおりに剛体として動かし、脚は 6 関節だけを
  足の目標に合わせて解く（脚は 6 関節で足の 6 つの座標を決めるので、IK の脚とはほかの目標の引きの分しか違わない）。床から離れて
  胴に完全についていく脚は、胴に対する姿勢をそのまま保つ。脚だけで解いたとき、部位どうしが学習側の衝突の形で 3 mm より深く
  重なるか（IK は自分の形で 2 mm 離すだけで、学習側の箱とは大きさが違う）、止めた足に届かないフレームは、IK で解き直す。
  姿勢と S は、変わっていないフレームでは前の結果を使う。

足首の傾き（3）について：足の裏は平らな板（62 × 40 mm）で、足首の位置を保ったまま足を左右に回しても、体の位置は変わらないので

PICO の歩き 0→23→68、123.8→0.1。LAFAN1 walk3_subject5 4→27→54、155.5→106.7（股が範囲の端にあって、足を止められない。下）。

滑りが残るところ：脚だけでは止めた足に届かないフレーム（股の pitch か roll が範囲の端）では、IK の脚のままにしていて、足が
滑る。人の姿勢が Microban の関節の範囲を超えるところで、LAFAN1 の前に深くかがむ歩き（walk3_subject5 は胴が中央値 52° 前に
傾き、股の pitch は寄せる前から中央値 −88°。範囲は ±90°）と、足を体の中心近くに置く歩き（股の roll が ±25° の端）に多い。
そこで足を止めるには胴を動かすしかなく、試した 4 通りはどれも ZMP を悪くした（無作為の 32 本：LAFAN1 8 本の最初の 60 秒と
CMU 24 本、計 23 分。胴の加速度は根の水平の 2 階差分の p95）：

| 止められない足の扱い | 滑るフレーム % | 片足 S の中 % | 両足 S の中 % | 学習側で外す % | 胴の位置の誤差 mm | 胴の加速度 p95 m/s² |
|---|---|---|---|---|---|---|
| IK の脚のまま（採用） | 25.0 | 43.9 | 73.3 | 24.2 | 1.9 | 3.2 |
| フレームごとに、胴を届かない分だけ動かす（10 mm まで） | 18.7 | 40.5 | 70.6 | 23.1 | 2.3 | 5.1 |
| 同（20 mm まで） | 15.3 | 36.6 | 67.7 | 25.2 | 2.9 | 6.0 |
| 同（上限なし。それでも届かなければ止めた足の重みを 100 倍にした IK） | 4.0 | 13.6 | 60.3 | 28.1 | 5.0 | 10.3 |
| 届かない分を 1 段目のずらしの計画に入れる（なめらかな B スプライン） | 22.9 | 41.0 | 71.3 | 26.2 | 1.9 | 3.4 |

フレームごとに胴を動かすと、胴がフレームごとに跳び（上限なしでは、寄せる前の胴の位置の差のフレーム間の変化の p99 が LAFAN1 の 8 本で 18〜39 mm）、ZMP が
外れる。なめらかに計画すると跳ばないが、計画の上では届かない分を埋めても、滑りはほとんど減らなかった（理由は確かめていない。
推測では、足の向きの分と、ずらしたあとも股が端に残る分）。そのため、ZMP を先にし、関節の範囲を超えるところの滑りは例外として残した。

ほかに残る問題：

- 片足のフレームで ZMP が S の中にあるのは全体で 49%（ずらしだけでは 32%）。入らないフレームの多くは 1〜4 を上限まで使っても
  入らないところ（股の roll と脚の届く範囲。PICO は 26%）。膝や手も着くフレームは変えない。
- 学習側で外す割合は 14.2 → 20.9%（LAFAN1 19.0 → 29.6%、CMU 12.9 → 17.6%、PICO 6.7 → 13.7%。歩きでは LAFAN1 3.0 → 12.8%、
  CMU 3.3 → 8.3%）。増えたのは関節の跳び（LAFAN1 のフレームの 1.3 → 3.0%）と部位の重なり（1.0 → 1.4%）。無作為の 32 本では、
  跳びの多くは足が着く・離れる前後の膝と、腕の分かれ道の跳び。脚を足へなめらかに入れる直しと、学習側の形で重なりを確かめる直しで
  24.2 → 21.7% に減らしたが、ずらしだけの版よりまだ多い。
- 前後の速さのばらつきは 0.090 → 0.113 m/s に増えた（CMU の歩きで 0.052 → 0.087。1 歩ごとに止まっては進む）。
- 全データに 2 時間 43 分（6 並列）かかる。1 時間にするには、写しに要らない学習側の読み込み（1 プロセス 1.1 GB）を外して並列を
  増やすか、IK で解き直すフレーム（重なりと届かない足。LAFAN1 walk3_subject5 では 1 フレームを平均 14 回）を減らす必要がある。

- 寄せたデータは、学習用・評価用・PICO の評価用のどれも寄せた写しになる。遠隔操作でその場で写す処理には寄せも足の固定も
  入っていない。寄せたデータで学習するなら、その場の写しにも同じ処理が要る（学習と実機の参照を揃えるため。案は下）。

その場の写し（実機の操縦）での寄せ方の案（作っていない）：

- ZMP には加速度が要り、先読みがないので、参照を当てはめの窓の半分（0.15 秒）遅らせ、遅らせた分の窓で同じ当てはめを使う。
- 寄せの量は、クリップ全体の代わりに、遅らせた窓（例えば過去 0.5 秒と遅らせた 0.15 秒）の中の最小二乗を毎周期解く（窓を進めて
  解き直す）。応答は IK を回し直さず、HOME の近くで前もって取った値（ずらし 1 mm あたりの ZMP の動き）を使う。IK は 1 周期 1 回。
- 床にある部位は、操縦者の足の高さと速さ（トラッカー）で決める。足の固定は区間の頭から 1 フレームずつ前へ作るので、そのまま
  使える。部位が離れる前の移しは、離れる時刻を前もって知れないので、足が上がり始めてから遅らせた 0.15 秒の中で行う（間に合わ
  ない分は ZMP が外に出る）。
- 遅れが 0.15 秒増えることと、寄せの間に合わない分を、学習側で同じ遅れを入れた参照で確かめる必要がある。

## 外すもの

1. **腕の反転**（`finalize`）：肩を 180° 回して肘を逆に曲げた、人と違う腕の解。3 フレーム以上続くものを、学習側と同じ前後 0.2 秒と一緒に切る。
   学習側の規則では反転したフレームの一部しか落ちないため。
2. **学習側の除外の規則**（`build`、`src/mjlab_microban/wholebody/data/preprocess.py`）：床へのめり込み、体どうしの入り込み、
   関節の範囲の外、関節の跳び、浮き、と次の支えのない姿勢。当たったフレームの前後 0.2 秒も落とし、22 フレーム未満の残りは捨てる。
3. **支えのない姿勢**（`unsupported`）：胴が立っていて（鉛直から 45° 以内）、重心がほぼ止まっていて（床に沿った速さが 0.1 m/s 未満）、
   ロボットの重心の床への投影が、床から 2.5 cm 以内にある衝突形状の角の凸包から 1 cm を超えて外れた状態が、1 秒を超えて続く区間。
   - 椅子や台に座る（人が座るとロボットは足だけが床に着き、胴が宙に浮く）、床に座る（脚が人のように畳めず、胴が床に届かない）、
     手すりや壁、相手に寄りかかる、などの sim にない支えを前提にした区間。
   - 重心がほぼ止まっている条件：ZMP（支えの中にしかない）は、重心から（重心の高さ / g）× 加速度だけずれる。
     速さが 1 秒の間 0.1 m/s 未満なら、両者の平均の差は (0.18 m / g) × (2 × 0.1 m/s) / 1 s = 3.6 mm 以内なので、
     重心が支えの外に 1 秒とどまる参照は追えない（この高さの倒立振子は 0.13 秒で離れていく）。
     重心が動いている区間（走る、跳ぶ、倒れる、踏み出す）は判定しない。この条件がないと、幅を狭めたときに跳びや走りにも当たる。
   - 幅 1 cm の根拠（今の LAFAN1、CMU、PICO の写しで測った）：

     | 幅 | LAFAN1 の支えのいらない動き（walk、run、sprint、dance、fight、jumps など）で、重心が止まった 1 秒の区間のうち幅を超えて外れる割合 | CMU の座り（cmusit）で印が付く割合 |
     |---|---|---|
     | 0.5 cm | 0.65% | 17.2% |
     | 1 cm | 0.28% | 16.3% |
     | 1.5 cm | 0.03% | 13.0% |
     | 2 cm（前の規則、速さの条件なし） | — | 9.0% |

     1 cm は、写し自体の誤差（支えのいらない動きで重心が足の外に出る量）より大きく、座っている区間のほとんどより小さい。
     2 cm では、たとえば CMU 114_05 の最初の 1.4 秒（重心が足の外に 1.8〜1.9 cm、椅子に座っている）が残っていた。
   - 支えの範囲を床から 2.5 cm 以内の角まで広く取るのは、写しで立ち足が浮くため。LAFAN1 の支えのいらない動きで止まって立つとき、
     高いほうの足が床から 1〜2.5 cm にあるフレームが 7% ある。1.5 cm に詰めると、立っている区間にも印が付く
     （cmudance 0.5 → 4.0%、cmumisc 1.1 → 2.7%）。
   - 種類の名前ではなく姿勢で決めるので、座りでも重心が足の上にある区間（立ち上がる直前など）は sim でもできるので残る。
   - 寝る・這う動き（胴が 45° を超えて倒れている）は判定しない。胴が床の近くにあり、床に降りても姿勢がほとんど変わらないため。
   - 宙にある区間（接地点がない）は、浮きの規則が受け持つ。
   - PICO の膝立ち（`picoany_kneel*`、`picoany_balance`、`picoany_squat_kneel_and_lounge`）が外れるのは、写しで膝が床に届かないため。
     元の録画（G1）では膝が床に着いている（G1 の膝の関節の中心が床から約 4 cm）が、写した姿勢では足が最も低く、
     膝（tibia）が床から 2〜5 cm 浮いて、片足だけで立つ参照になる。床合わせは最も低い点（足）を床に置いていて、そのとおりに動いている。
     膝立ちそのものは sim でもできるが、膝を床に着けるように写す方法は今はない。
   - この規則で新しく外れた量（それまでの規則で残っていた分から。今の写しで測った）：

     | データ | 学習用（分） | 評価用（分） | 主な種類（外れた分） |
     |---|---|---|---|
     | LAFAN1 | 177.2 → 175.6 | 46.63 → 46.56 | obstacles 0.89、ground 0.35、aiming 0.15、fightAndSports 0.12、fallAndGetUp 0.11 |
     | CMU | 418.3 → 414.0 | 99.4 → 98.4 | cmumisc 2.64（動物のまね：panda、bird など）、cmuclimb 1.28（台や椅子に座る）、cmusit 0.89（外れる割合 2.2 → 19.4%）、cmuwalk 0.24、cmuground 0.22 |
     | PICO（評価用） | — | 62.1 → 59.2 | picoany 2.18（膝立ち）、picoteleopit 0.60、picotwist 0.13 |

種類ごとに外れた割合が 30% を超えると、`report.json` と `build` の表に `REVIEW` が付く。学習の前に写しを見直す（`quality` の内訳、`render` の動画）。
