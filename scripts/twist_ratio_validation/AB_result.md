条件はどれも同じです：学習シード 42、4096 envs。

- **採用：A**
- **理由：** 決められた採り方では、両方とも合格のときは A を採ります。A と B はどちらも 166 以上でした。
- 補足として、B のほうが長いですが、A も旧報酬と同程度の伸び方をしています（200 回で 171、300 回で 174、400 回で 183）。

## 何が問題で、何を直したか

- **最初の形 `speed - error`：** 立っているだけでは報酬が 0 になります。旧報酬では exp の追従項が、序盤の正の報酬の約半分を占めていました。そのため、最初の形では生き残る動機が弱く、エピソードが約 45 ステップのままでした。
- **途中で入れた修正：** 上下の速度と、横転・前転の角速度を、「指令にない動き」として誤差に入れました。
  - 理由は、指令の方向へ倒れていく間にも速さの報酬が入っていたためです。
  - これだけではエピソード長は伸びませんでしたが、修正自体は残しています。

**報酬の項：** `twist_ratio_velocity_reward(env, command_name="twist", trunk_pitch=<HOME の前傾>)`

```
reward = base + speed - direction_penalty * error      （base 1、direction_penalty 1）
```

各量の定義は次のとおりです。

- **正規化：** 前・横・旋回を、それぞれ指令の最大値で割ります（既定は 0.7 m/s、0.3 m/s、1.5 rad/s）。
- **記号：**
  - c^：正規化した指令
  - n = |c^|
  - u = c^ / n
  - p = v^・u（正規化した実際の速度の、指令方向の成分）
- **speed** = clamp(p, 0, n) / max(n, 0.2)
  - 指令方向の成分だけを使います。指令を超えた分は報酬になりません。
- **error** = sqrt(|v^ - clamp(p, 0, n) u|^2 + |w^|^2) + max(0, -p)
  - 次の動きをすべて減点します：横にそれた分、行き過ぎた分、反対向きの分。
  - 反対向きの分は 2 回数えます。
  - w^ は指令にない動きです（上下の速度 /0.7、横転・前転の角速度 /1.5）。

この形にしたときの性質は次のとおりです。

- 立って静止しているときは 1、指令どおりに動いているときは 2 です。
- 指令が出せる速さを超えているとき、最も報酬が高いのは「比を保ったまま、出せる最大の倍率」で動くことです。
  - これはテスト `test_best_reachable_twist_keeps_the_ratio_at_the_largest_scale` で確認しています。

### B2 も不採用 → B3（時間方向に平滑化した有界な形）（2026-10-06 21:20、コミット `cf91eec`）

### B4（2026-10-07 00:20、コミット `6d12626`）: 本線への推奨を B4 に更新

**式:** 単位はそろえた（正規化した）もの。p = v・u、s = clamp(p, 0, n)/n、e = ずれ（垂直成分、行き過ぎ、指令にない動き）。

- 0.5 s の平滑化は B3 と同じ。
- 小さな指令（立ち止まりを含む）の速さの扱いも B3 と同じ。
- 歩行での重みは 4。最大は 8、止まっているときは 4 で、B2/B3（重み 8 × [0, 1]）と同じ幅になる。

**値の決め方:**

- a = 0.4：どんなにずれていても、進めば 1 + 0.4 × s 以上になる。
- σ = 0.15：一致に近づくと急に上がる。旋回時の平滑化後のずれ（0.11〜0.15）で、増やせる分の約半分が残る。
